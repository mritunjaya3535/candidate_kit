# REVIEW.md

List every defect you found in the starter `app/main.py` (helpers and endpoints). For each one:

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `health()` (L72-74) | Returns 200 without checking MongoDB connectivity. | Stop MongoDB service; `GET /health` still returns 200 instead of 503. | Added `client.admin.command("ping")` inside try/except block; raises HTTP 503 on failure. |
| 2 | `compute_late_minutes()` (L33-37) | Replaces hour/minute on punch_in datetime directly without IST timezone anchoring or overnight shift reference. | Punch-in at 00:15 on an overnight shift (22:00-06:00) computes shift start as 22:00 on the same calendar day, yielding negative or incorrect elapsed minutes. | Anchored shift start to the attendance date in IST (`UTC+05:30`) and calculated difference from that instant. |
| 3 | `compute_late_minutes()` (L37) | Grace period logic (`minutes > 10`) fails strict 10:00 rule (R2) due to integer truncation before comparison. | Punch-in at 09:40:01 on a 09:30 shift: `int(601 / 60)` is 10, so condition `10 > 10` is false, returning 0 instead of 10. | Compare elapsed seconds strictly: `diff.total_seconds() <= 600` returns 0; otherwise `math.floor(diff.total_seconds() / 60)`. |
| 4 | `compute_work_hours()` (L40-41) | Uses Python's built-in `round()`, which uses banker's rounding (round-half-to-even) instead of round-half-up (R4). | `(29250 / 3600) = 8.125`; `round(8.125, 2)` gives `8.12` instead of `8.13`. | Implemented `Decimal.quantize(Decimal("0.01"), rounding=ROUND_HALF_UP)`. |
| 5 | `compute_overtime()` (L44-47) | Assumes shift end is on the same calendar date as `date_str`, breaking overnight shifts (R1, R3). | Shift 22:00-06:00 on 2026-07-06 with punch-out at 06:40 next day compares 06:40 against 06:00 of 2026-07-06 (24 hours off). | Checked if `shift_end <= shift_start`; if overnight, shift end date is incremented by 1 calendar day. |
| 6 | `compute_overtime()` (L47) | Missing 30-minute threshold: returns any positive minutes. | Punch-out 15 minutes after shift end returns 15 instead of 0 (R3 requires >= 30 min). | Added threshold check: `minutes if minutes >= 30 else 0`. |
| 7 | `create_employee()` (L79-83) | Check-then-insert race condition allows duplicate `emp_code` under concurrent requests. | Two parallel `POST /employees` requests with identical `emp_code` both succeed with 201. | Created unique index on `emp_code` at startup; caught `DuplicateKeyError` and raised HTTP 409. |
| 8 | `create_employee()` (L53-60, L78) | Missing input validations: `shift_start == shift_end` accepted; `emp_code`, `email`, lengths, and date formats unvalidated. | `POST /employees` with `shift_start: "09:30", shift_end: "09:30"` returns 201 instead of 422. | Added regex and length constraints on Pydantic model and explicit validation that `shift_start != shift_end`. |
| 9 | `create_employee()` (L82-85) | `created_at` generated as local naive datetime and returned as a datetime object rather than epoch milliseconds. | Response `created_at` is an ISO string/datetime object; does not match epoch milliseconds schema. | Set `datetime.now(timezone.utc)` and converted to integer epoch milliseconds in response. |
| 10 | `list_employees()` (L93) | Off-by-one pagination offset: `skip = page * page_size` skips page 1 completely. | `GET /employees?page=1&page_size=20` skips the first 20 records and returns records 21-40. | Changed formula to `skip = (page - 1) * page_size`. |
| 11 | `list_employees()` (L94) | `total` count ignores filter `q`: counts entire collection regardless of department. | `GET /employees?department=Sales` returns total count of all employees in all departments. | Changed to `db.employees.count_documents(q)`. |
| 12 | `list_employees()` (L95) | Missing sort order: results returned in arbitrary MongoDB natural order. | Inconsistent ordering across identical requests. | Added `.sort("emp_code", 1)` to cursor. |
| 13 | `list_employees()` (L89) | `page_size` allows unbounded values, violating contract maximum of 100 (R10). | `GET /employees?page_size=5000` returns 5000 records instead of 422. | Added FastAPI `Query(20, ge=1, le=100)`. |
| 14 | `punch_in()` (L101-105) | Check-then-insert race condition allows duplicate punch-ins for the same employee and date. | Concurrent identical punch-in requests both insert documents and return 201. | Created compound unique index `(emp_code, date)` on `attendance_logs`; caught `DuplicateKeyError` and returned 409. |
| 15 | `punch_in()` (L101) | Unhandled non-existent employee: if `emp` is None, `emp["shift_start"]` raises unhandled `TypeError` (500). | `POST /attendance/punch-in` with unknown `emp_code` returns 500 instead of 404. | Added employee existence check, raising HTTP 404 if not found. |
| 16 | `punch_in()` (L102-103) | Attendance date calculation uses server local time rather than IST and ignores overnight shift rule R1. | Punch-in at 01:30 IST on an overnight shift (22:00-06:00) gets assigned to today instead of previous day. | Implemented `get_attendance_date` with IST conversion and overnight check (punch-in < shift_end belongs to previous day). |
| 17 | `punch_in()` (L66) | Accepts invalid status values such as `ABSENT` or `LEAVE` on punch-in. | `POST /attendance/punch-in` with `status: "ABSENT"` creates a record instead of 422. | Restricted status in Pydantic schema to regex `^(PRESENT|WFH|ON_DUTY)$`. |
| 18 | `punch_in()` (L65) | Missing validation for `punched_at`: accepts seconds (< 100000000000), floats, or out-of-range values. | `punched_at: 1720000000` accepted instead of returning 422. | Added `Field(None, ge=100000000000, le=4102444800000)` validation. |
| 19 | `punch_in()` (L119) | Returns internal `id: str(res.inserted_id)`, violating API schema which disallows `id` or `_id`. | Response body includes `"id": "..."` field. | Formatted response according to `AttendanceRecord` schema without `_id` or `id`. |
| 20 | `punch_in()` (L102) | Instants not truncated to whole seconds before calculation and storage (R1). | Punch-in with milliseconds stored as-is, causing discrepancies in late minutes. | Truncated milliseconds `(ms // 1000) * 1000` before storing and calculating. |
| 21 | `list_attendance()` (L144-150) | In-memory sort and slicing loads the entire collection into memory on every request. | On ~100k records, request causes high latency and memory exhaustion. | Pushed sorting, skipping, and limiting directly to MongoDB query cursor using indexes. |
| 22 | `list_attendance()` (L145) | Sorts only by `date` descending; misses secondary sort by `emp_code` ascending. | Non-deterministic ordering for multiple records on the same date. | Changed sort to `[("date", -1), ("emp_code", 1)]`. |
| 23 | `list_attendance()` (L127-128) | Missing validation for date range: `date_from > date_to` does not return 422. | `GET /attendance?date_from=2026-08-10&date_to=2026-08-01` returns 200 with empty items instead of 422. | Added explicit check raising HTTP 422 when `date_from > date_to`. |
| 24 | `list_attendance()` (L148-150) | Returns raw BSON datetimes and leaks `id` field; misses defaulting `history: []` and `half_day: False` on legacy records. | Schema validation failure on output format. | Transformed each record with `format_attendance_record`, converting datetimes to epoch ms and supplying schema defaults. |
| 25 | Startup | No database indexes created at startup. | Sluggish queries, index scans missing in explain plans, and lack of database-enforced concurrency guarantees. | Implemented `init_indexes()` creating all required unique and compound indexes idempotently at startup lifespan. |

Also note anything you looked at and decided was **not** a defect, and why:

1. **`emp_code` used as human-readable business key instead of MongoDB `_id`**: Looked at whether `emp_code` should be mapped to an internal ObjectId. Decided it is not a defect because DATA_MODEL.md explicitly specifies that `emp_code` is the customer-supplied immutable identifier everywhere and `_id` must never appear in the API.
2. **Absence of `_id` or `id` fields in API responses**: Verified against openapi.yaml schemas. Confirmed that attendance records and employees are identified by natural keys (`emp_code` and `(emp_code, date)`), and omitting `_id` is an explicit requirement.
3. **Storing precomputed derived fields in `attendance_logs`**: Examined whether `work_hours`, `late_minutes`, `overtime_minutes`, and `half_day` should be recomputed on the fly. Confirmed this is not a defect; the problem specification explicitly mandates that derived fields must be computed and stored at punch/regularization time, and analytics must read the stored values.
